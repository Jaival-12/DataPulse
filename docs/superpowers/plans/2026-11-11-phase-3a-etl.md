# DataPulse Phase 3A ETL Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a synchronous, testable backend ETL engine that executes validated transformations on uploaded datasets and publishes separate processed datasets.

**Architecture:** Add SQLAlchemy persistence and an Alembic revision; validate step configurations with Pydantic; apply each supported operation through a dedicated safe transformation service; orchestrate source loading, step logs, execution status, and atomic output publication through a pipeline service and router. Keep APIs under `/api`, source files unchanged, and processed outputs under generated paths in a separate storage directory.

**Tech Stack:** Existing FastAPI, SQLAlchemy, Alembic, Pydantic v2, Pandas, NumPy, pytest, and SQLite test fixtures; no additional dependency.

**Spec:** `docs/superpowers/specs/2026-11-11-phase-3a-etl-design.md`

## Global Constraints

- Preserve existing upload, preview, profiling APIs and frontend.
- Never overwrite the original source file.
- Use SQLite-compatible JSON with JSONB on PostgreSQL; migrations remain Alembic-managed.
- Apply transformation steps in order and stop on first failure.
- Never use `eval()`, `exec()`, user-derived paths, or publish partial successful output.
- Execution remains synchronous and bounded by existing profile-size limits.
